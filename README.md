# burp-agent-mcp

MCP-шлюз между языковой моделью и Burp Suite для авторизованного тестирования на тестовых и стейджинг-окружениях.

Модель видит только инструменты шлюза. Scope, режим, окружение и лимиты проверяет код шлюза, а не промпт. Каждое действие пишется в аудит-лог с хеш-цепочкой.

## Что умеет

- Чтение: история Burp, сводка эндпоинтов, покрытие OpenAPI, находки сканера, поиск по телам JavaScript, отчёты.
- Работа по URL: `request_url` шлёт запрос по адресу из `scope_urls`.
- Сканер по URL: проверки анонимного доступа, соседних id, кавычки и отражения. Только GET, HEAD, OPTIONS, с потолком запросов и паузами.
- Repeater и Intruder: повтор с изменениями и последовательный перебор одной позиции с жёсткими лимитами.
- Браузер: переходы, клики, заполнение полей (пароли и поля с секретами отклоняются), скриншоты. Весь трафик идёт через прокси Burp.

Активные действия работают только при `environment` равном `test`, `stage`, `staging` или `lab`.

## Установка

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt playwright websockets
./.venv/bin/python -m playwright install chromium
cp policy.example.json policy.json
```

Расширение Burp для пассивных находок и экспорта JavaScript собирается из `burp-extension/AgentFindings.java` и загружается в Burp вручную (Extensions → Add → Java).

## Настройка scope

Scope задаёт владелец, не модель:

```bash
./.venv/bin/python scope_cli.py show
./.venv/bin/python scope_cli.py env test
./.venv/bin/python scope_cli.py add-url https://app.example.test/
./.venv/bin/python scope_cli.py add-spec ~/specs/openapi.json
```

После изменений перезапустите сессию: шлюз читает политику при старте, а при правке файла в сессии активные действия блокируются.

## Тесты

```bash
./run_tests.sh
```

Браузерные тесты нужен Chromium (`playwright install chromium`). Тесты используют подменённый upstream и локальные тестовые серверы, сеть наружу не нужна.

## Ограничения

- Находки сканера — кандидаты для ручной проверки, а не подтверждённые уязвимости.
- Шлюз не защищает от модели, которая может писать `policy.json` и перезапустить шлюз. Для этого владелец файла должен быть отдельным пользователем ОС.
- Ответы целей, даже очищенные, уходят в модель. Не используйте шлюз с реальными персональными данными без согласования.
